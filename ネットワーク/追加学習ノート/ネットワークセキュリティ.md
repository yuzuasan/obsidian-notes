# ネットワークセキュリティ

ネットワークセキュリティは、**不正アクセスや攻撃からネットワーク・システムを保護するための仕組み**。

重要なのは、単一の対策ではなく、複数の防御を組み合わせること。

---

# ACL

ACL（Access Control List）は、**通信を許可するか拒否するかをルールで制御する仕組み**。

主に、

* 送信元IPアドレス
* 宛先IPアドレス
* プロトコル
* ポート番号

などを条件にする。

```text
通信
 ↓
ACL
 ↓
許可 / 拒否
```

---

# ステートフルファイアウォール

ステートフルファイアウォールは、**通信の状態（セッション）を追跡して通信を制御するファイアウォール**。

例えば、

```text
Client → Server
```

という接続を記録し、その通信に対する戻りの通信を許可できる。

単純なパケット単位のフィルタリングよりも、通信の状態を考慮した制御ができる。

---

# IDS

IDS（Intrusion Detection System）は、**不正アクセスや攻撃を検知する仕組み**。

```text
通信
 ↓
IDS
 ↓
攻撃を検知
 ↓
通知・記録
```

基本的には、攻撃を**検知・通知すること**が目的。

---

# IPS

IPS（Intrusion Prevention System）は、**不正アクセスや攻撃を検知し、通信を遮断する仕組み**。

```text
通信
 ↓
IPS
 ↓
攻撃を検知
 ↓
通信を遮断
```

IDSとの違いは、**検知だけでなく防御まで行うこと**。

---

# WAF

WAF（Web Application Firewall）は、**Webアプリケーションへの攻撃を防御するための仕組み**。

HTTP / HTTPSの通信内容を検査し、Webアプリケーションに対する攻撃を防ぐ。

代表例：

* SQLインジェクション
* クロスサイトスクリプティング（XSS）
* 不正なHTTPリクエスト

```text
Client
  |
WAF
  |
Web Server
```

通常のネットワークファイアウォールが主にIPやポートなどを制御するのに対し、WAFは**Webアプリケーション層の通信を検査する**。

---

# DDoS

DDoS（Distributed Denial of Service）は、**多数の端末から大量の通信を送り、サービスを利用できなくする攻撃**。

```text
攻撃端末 ─┐
攻撃端末 ─┼→ Internet → Server
攻撃端末 ─┘
```

大量の通信によって、

* 回線帯域
* サーバーリソース
* ネットワーク機器

などを消費させる。

対策として、CDNやDDoS対策サービス、トラフィック制御などを利用する。

---

# プロキシ

プロキシは、**クライアントと通信先の間に入り、通信を中継する仕組み**。

```text
Client
  |
Proxy
  |
Internet
```

クライアントが直接通信先へ接続するのではなく、プロキシを経由して通信する。

---

# フォワードプロキシ

フォワードプロキシは、**クライアント側に設置して外部への通信を中継するプロキシ**。

```text
社内PC
  |
Forward Proxy
  |
Internet
```

主な用途：

* インターネットアクセスの制御
* URLフィルタリング
* アクセスログ取得
* キャッシュ
* 社内端末からの外部通信の集約

---

# リバースプロキシ

リバースプロキシは、**サーバー側に設置して外部からの通信を中継するプロキシ**。

```text
Internet
   |
Reverse Proxy
   |
Web Server
```

主な用途：

* Webサーバーの保護
* 負荷分散
* TLS終端
* アクセス制御
* 複数Webサーバーへの振り分け

ロードバランサーとして動作することもある。

---

# DMZ

DMZ（非武装地帯）は、**インターネットなどの外部ネットワークからアクセスされるサーバーを、社内ネットワークから分離して配置するネットワーク領域**。

```text
Internet
    |
 Firewall
    |
   DMZ
    |
 Firewall
    |
社内ネットワーク
```

WebサーバーなどをDMZに配置し、万が一侵害されても社内ネットワークへ直接影響が及ばないようにする。

---

# ネットワークセグメンテーション

ネットワークを複数の領域に分割し、**不要な通信を制限する考え方**。

```text
Internet
   |
 DMZ
   |
Web
   |
Application
   |
Database
```

例えばWebサーバーからデータベースへの必要な通信だけを許可する。

攻撃者が1台のサーバーを侵害した場合でも、他のネットワークへの横展開を防ぎやすくなる。

---

# イースト・ウェスト通信

イースト・ウェスト通信は、**同一組織・データセンター内部などでシステム間を移動する通信**。

```text
Web
 |
Application
 |
Database
```

内部通信を適切に制御することで、侵害後の横展開を防ぐ。

---

# ノース・サウス通信

ノース・サウス通信は、**外部ネットワークと内部ネットワークの間を流れる通信**。

```text
Internet
   ↓
Firewall
   ↓
社内ネットワーク
```

ファイアウォールなどで外部から内部への通信を制御する。

---

# ゼロトラスト

ゼロトラストは、**ネットワークの内部・外部という場所だけを信頼せず、通信やアクセスごとに検証する考え方**。

基本的な考え方：

**「何も信頼せず、常に検証する」**

例えば、

* 利用者の認証
* 端末の状態確認
* アクセス先
* 権限
* 通信内容

などを確認してアクセスを制御する。

---

# 多層防御

ネットワークセキュリティでは、複数の防御手段を組み合わせる。

```text
Internet
   |
Firewall
   |
 IDS / IPS
   |
  DMZ
   |
  WAF
   |
Application
   |
Database
```

1つの対策を突破されても、別の対策で攻撃を防ぐことが目的。

---

# セキュリティ機器の役割

| 仕組み       | 主な役割            |
| --------- | --------------- |
| ACL       | 通信の許可・拒否        |
| ファイアウォール  | 通信を制御           |
| IDS       | 攻撃を検知・通知        |
| IPS       | 攻撃を検知・遮断        |
| WAF       | Webアプリへの攻撃を防御   |
| フォワードプロキシ | 内部端末の外部通信を中継    |
| リバースプロキシ  | 外部からサーバーへの通信を中継 |
| DMZ       | 外部公開サーバーを分離     |
| セグメンテーション | ネットワークを分離       |
| ゼロトラスト    | 常に検証してアクセス制御    |

---

# 覚えておくポイント

* ACLは通信をルールに基づいて許可・拒否する
* ステートフルファイアウォールは通信状態を追跡して制御する
* IDSは攻撃を検知・通知する
* IPSは攻撃を検知して通信を遮断する
* WAFはWebアプリケーションへの攻撃を防御する
* DDoSは多数の端末から大量通信を送り、サービスを妨害する
* フォワードプロキシはクライアント側の外部通信を中継する
* リバースプロキシはサーバー側で外部からの通信を中継する
* DMZは外部公開サーバーを社内ネットワークから分離する
* セグメンテーションはネットワークを分離して被害の拡大を防ぐ
* イースト・ウェスト通信は内部ネットワーク間の通信
* ノース・サウス通信は外部と内部の間の通信
* ゼロトラストは「何も信頼せず、常に検証する」という考え方
* 多層防御では複数のセキュリティ対策を組み合わせる
