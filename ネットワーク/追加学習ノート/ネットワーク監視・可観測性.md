# ネットワーク監視・可観測性

ネットワーク監視は、**ネットワークや機器の状態を継続的に確認し、障害や異常を検知する仕組み**。

可観測性は、**システムから得られる情報をもとに、内部で何が起きているかを把握する考え方**。

---

# ネットワーク監視

主に以下の情報を監視する。

* 疎通
* ポート
* 通信遅延
* パケットロス
* 帯域使用率
* インターフェースエラー
* CPU
* メモリ
* ログ

```text
ネットワーク機器
      |
      ↓
   監視システム
      |
 ┌────┴────┐
 ↓         ↓
正常      異常
           |
         通知
```

---

# Ping監視

Pingを使用して、**対象機器とのIPレベルの疎通を確認する監視**。

```text
監視サーバー
     |
   ICMP
     ↓
   Server
```

確認できる主な情報：

* 疎通できるか
* 応答時間
* パケットロス

ただし、Pingが成功しても**アプリケーションが正常とは限らない**。

---

# ポート監視

TCPなどのポートへ接続を試み、**サービスが接続可能か確認する監視**。

例えば、

```text
TCP 443 → HTTPS
TCP 22  → SSH
TCP 3306 → MySQL
```

Pingが成功していても、対象サービスのポートが閉じていれば通信できない。

---

# SNMP

SNMP（Simple Network Management Protocol）は、**ネットワーク機器などの状態を取得・監視するためのプロトコル**。

```text
監視サーバー
    |
   SNMP
    ↓
ネットワーク機器
```

取得できる代表例：

* CPU使用率
* メモリ使用率
* インターフェース通信量
* インターフェースエラー
* 機器の状態

---

# Syslog

Syslogは、**ネットワーク機器やサーバーなどが出力するログを収集・転送する仕組み**。

```text
Router ─┐
Switch ─┼→ Syslogサーバー
FW ─────┘
```

障害発生時の原因調査や、セキュリティイベントの確認に利用する。

---

# メトリクス

メトリクスは、**システムの状態を数値として表したデータ**。

代表例：

* CPU使用率
* メモリ使用率
* 帯域使用率
* 通信量
* レスポンスタイム
* パケットロス率
* エラー数

時系列で記録することで、障害発生前後の変化を確認できる。

---

# ログ

ログは、**システムやネットワーク機器で発生したイベントを記録した情報**。

例えば、

```text
接続成功
接続失敗
認証失敗
インターフェースDown
設定変更
```

など。

メトリクスが「どの程度悪化しているか」を見るのに対し、ログは「何が起きたか」を調べるのに向いている。

---

# トレース

トレースは、**1つのリクエストが複数のサービスを通過する過程を追跡する情報**。

```text
Client
  |
Load Balancer
  |
Web
  |
Application
  |
Database
```

例えばレスポンスが遅い場合、

```text
Web → 10ms
Application → 20ms
Database → 500ms
```

のように、どこで時間がかかっているかを確認できる。

---

# 可観測性

可観測性では、主に以下の3つを組み合わせてシステムの状態を把握する。

```text
        可観測性
             |
    ┌────────┼────────┐
    ↓        ↓        ↓
 メトリクス  ログ    トレース
```

### メトリクス

**何がどの程度起きているか**

### ログ

**何が起きたか**

### トレース

**処理がどこを通り、どこで時間がかかっているか**

---

# レイテンシ

レイテンシは、**通信や処理にかかる時間**。

例えば、

```text
Client
  |
  | Request
  ↓
Server
  |
  | Response
  ↓
Client
```

応答時間が通常100msなのに、突然2秒になった場合は、ネットワークやサーバーなどのどこかで遅延が発生している可能性がある。

---

# パケットロス

パケットロスは、**送信したパケットが宛先に正常に届かない状態**。

パケットロスが発生すると、

* 通信速度低下
* 再送増加
* TCP通信の遅延
* アプリケーションの応答遅延

などにつながる。

---

# 帯域使用率

ネットワーク回線やインターフェースが、**どの程度帯域を使用しているか**を表す。

```text
100Mbps回線

現在使用量：90Mbps
使用率：90%
```

帯域使用率が高い状態が続く場合、通信遅延やパケットロスにつながる可能性がある。

---

# インターフェースエラー

ネットワークインターフェースでは、通信エラーが発生することがある。

例えば、

* CRCエラー
* パケット破棄
* 入出力エラー
* インターフェースDown

など。

物理障害やケーブル、速度・二重化設定などの問題を疑う材料になる。

---

# アラート

アラートは、**異常や閾値超過を検知して通知する仕組み**。

例えば、

```text
CPU使用率 > 90%
通信量 > 80%
パケットロス > 10%
Interface Down
```

などを条件に通知する。

ただし、アラートが多すぎると重要な障害を見落とすため、**適切な閾値と通知設計**が重要。

---

# 監視による障害解析

障害発生時には、複数の情報を組み合わせて原因を絞り込む。

```text
アラート
  ↓
メトリクス確認
  ↓
ログ確認
  ↓
ネットワーク状態確認
  ↓
トレース確認
  ↓
原因特定
```

例えば、

```text
レスポンス遅延
    ↓
帯域使用率 → 正常
    ↓
パケットロス → 正常
    ↓
CPU → 正常
    ↓
DB処理時間 → 増加
    ↓
DB側の問題を疑う
```

**1つの監視情報だけで原因を断定しないこと**が重要。

---

# 監視と可観測性の違い

### 監視

「異常が発生していないか」を確認する。

```text
正常？
異常？
```

### 可観測性

「なぜその状態になっているのか」を調査できるようにする。

```text
何が起きた？
↓
どこで起きた？
↓
なぜ起きた？
```

そのため、可観測性ではメトリクス・ログ・トレースなどを組み合わせる。

---

# 覚えておくポイント

* ネットワーク監視は機器や通信の状態を継続的に確認する
* Ping監視はIPレベルの疎通を確認する
* ポート監視は特定サービスへの接続可能性を確認する
* SNMPはネットワーク機器などの状態を取得するために利用される
* Syslogは機器やサーバーのログ収集に利用される
* メトリクスは状態を数値で把握する
* ログは発生したイベントを確認する
* トレースはリクエストの処理経路を追跡する
* 可観測性ではメトリクス・ログ・トレースを組み合わせる
* レイテンシは通信や処理にかかる時間
* パケットロスは通信品質低下やTCP再送の原因になる
* 帯域使用率が高いと遅延やパケットロスにつながる可能性がある
* インターフェースエラーは物理障害などの調査材料になる
* アラートは異常を検知して通知する
* 障害解析では複数の監視情報を組み合わせる
* 監視は「異常を見つける」、可観測性は「なぜ起きたかを調べる」ための考え方
