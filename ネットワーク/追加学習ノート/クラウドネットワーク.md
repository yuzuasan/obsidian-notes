# クラウドネットワーク

クラウドネットワークは、**クラウド上に仮想的なネットワークを構築する仕組み**。

AWSではVPCを中心に、サブネット、ルートテーブル、インターネットゲートウェイ、NATゲートウェイなどを組み合わせてネットワークを構成する。

---

# VPC

VPC（Virtual Private Cloud）は、**クラウド上に構築する論理的なネットワーク空間**。

```text
VPC
├─ Public Subnet
├─ Public Subnet
├─ Private Subnet
└─ Private Subnet
```

VPC内にサブネットやルートテーブルなどを構成する。

---

# サブネット

サブネットは、**VPCのIPアドレス範囲を分割したネットワーク**。

例えば、

```text
VPC
10.0.0.0/16

├─ Public Subnet
│   10.0.1.0/24
│
└─ Private Subnet
    10.0.2.0/24
```

AWSでは、サブネットは特定のアベイラビリティゾーン（AZ）に属する。

---

# パブリックサブネット

インターネットゲートウェイを経由して、**インターネットとの通信経路を持つサブネット**。

```text
Internet
   |
Internet Gateway
   |
Public Subnet
   |
Server
```

ただし、サブネットがパブリックでも、インスタンス側に適切なIPやルーティング、セキュリティ設定が必要。

---

# プライベートサブネット

**インターネットから直接アクセスさせないサブネット**。

```text
Internet
   X
   |
Private Subnet
   |
Application Server
```

データベースなど、外部から直接アクセスさせたくないリソースを配置する。

---

# ルートテーブル

ルートテーブルは、**宛先ネットワークごとに通信をどこへ転送するかを定義する**。

例えば、

```text
宛先             転送先
10.0.0.0/16      local
0.0.0.0/0        Internet Gateway
```

プライベートサブネットから外部へアクセスする場合は、

```text
0.0.0.0/0 → NAT Gateway
```

などの経路を設定する。

---

# インターネットゲートウェイ

インターネットゲートウェイは、**VPCとインターネット間の通信を可能にするためのゲートウェイ**。

```text
Internet
   |
Internet Gateway
   |
VPC
```

パブリックサブネットからインターネットへ通信する場合などに使用する。

---

# NATゲートウェイ

NATゲートウェイは、**プライベートサブネットからインターネットへアクセスするために使用する仕組み**。

```text
Private Subnet
     |
 NAT Gateway
     |
Internet Gateway
     |
 Internet
```

例えば、プライベートサブネットのサーバーから、

* OSのアップデート
* 外部APIへのアクセス
* パッケージのダウンロード

などを行う場合に利用する。

**外部からプライベートサブネットへ直接接続するためのものではない。**

---

# セキュリティグループ

セキュリティグループは、**クラウド上のリソースに対する通信を制御する仮想ファイアウォール**。

例えば、

```text
Internet
   |
   ↓ TCP 443
Web Server
```

HTTPS（443）の通信だけを許可する、といった制御ができる。

主な特徴：

* インスタンスなどのリソース単位で適用
* 通信を許可するルールを設定
* ステートフル
* 戻り通信は許可ルールに基づいて自動的に許可される

---

# ネットワークACL

ネットワークACL（NACL）は、**サブネット単位で通信を制御する仕組み**。

セキュリティグループとの違い：

| 項目   | セキュリティグループ | ネットワークACL  |
| ---- | ---------- | ---------- |
| 適用単位 | リソース       | サブネット      |
| 状態   | ステートフル     | ステートレス     |
| ルール  | 許可         | 許可・拒否      |
| 主な用途 | リソース保護     | サブネット単位の制御 |

---

# ロードバランサー

ロードバランサーは、**複数のサーバーへ通信を分散する仕組み**。

```text
              ┌─ Server A
Client → LB ──┼─ Server B
              └─ Server C
```

主な目的：

* 負荷分散
* 可用性向上
* 障害時の切り離し

AWSでは、用途に応じてApplication Load Balancer（ALB）やNetwork Load Balancer（NLB）などを利用する。

---

# アベイラビリティゾーン

アベイラビリティゾーン（AZ）は、**クラウド事業者のリージョン内にある独立した障害単位**。

```text
Region
├─ AZ-A
│   ├─ Subnet
│   └─ Server
│
└─ AZ-B
    ├─ Subnet
    └─ Server
```

複数AZにシステムを分散することで、1つのAZに障害が発生してもサービスを継続しやすくなる。

---

# VPCピアリング

VPCピアリングは、**異なるVPC同士をプライベートに接続する仕組み**。

```text
VPC A
10.0.0.0/16
    |
VPC Peering
    |
VPC B
10.1.0.0/16
```

接続するだけでは通信できず、双方のルートテーブルなどに適切な経路設定が必要。

---

# トランジットゲートウェイ

トランジットゲートウェイは、**複数のVPCや拠点ネットワークを集中的に接続するための仕組み**。

```text
VPC A ─┐
VPC B ─┼─ Transit Gateway ── 拠点ネットワーク
VPC C ─┘
```

VPCが増えた場合に、VPC同士を個別に接続する構成よりもネットワークを管理しやすくなる。

---

# クラウドネットワークの基本構成

典型的なWebシステムでは、例えば以下のような構成になる。

```text
                 Internet
                    |
             Internet Gateway
                    |
              Public Subnet
                    |
            Load Balancer
                    |
          ┌─────────┴─────────┐
          ↓                   ↓
   Private Subnet       Private Subnet
      App Server           App Server
          |                   |
          └─────────┬─────────┘
                    ↓
                Database
```

外部公開が必要なものと、内部だけで利用するものをサブネットで分離する。

---

# クラウドネットワークの障害解析

クラウドで通信できない場合も、基本的には段階的に切り分ける。

```text
クライアント
    ↓
ロードバランサー
    ↓
セキュリティグループ
    ↓
サブネット
    ↓
ルートテーブル
    ↓
ゲートウェイ
    ↓
宛先
```

確認するポイント：

* IPアドレス・サブネットが正しいか
* ルートテーブルに必要な経路があるか
* インターネットゲートウェイが必要な場所に接続されているか
* NATゲートウェイが必要な通信に使用されているか
* セキュリティグループで通信が許可されているか
* ネットワークACLで通信が拒否されていないか
* ロードバランサーのヘルスチェックが正常か
* 複数AZ構成になっているか

---

# オンプレミスとの違い

クラウドでは、物理的なルーターやスイッチを直接管理するのではなく、**クラウド事業者が提供する仮想的なネットワーク機能を組み合わせて構成する**。

```text
オンプレミス
Router
Switch
Firewall
Load Balancer
     ↓
物理機器を管理


クラウド
VPC
Route Table
Security Group
Load Balancer
     ↓
クラウドサービスを組み合わせる
```

ただし、基本となる考え方はオンプレミスと共通している。

**IPアドレス → ルーティング → 通信制御 → 宛先**

という流れを理解しておくことが重要。

---

# 覚えておくポイント

* VPCはクラウド上の論理的なネットワーク空間
* サブネットはVPCのIPアドレス範囲を分割したもの
* パブリックサブネットはインターネットへの通信経路を持つ
* プライベートサブネットは外部から直接アクセスさせない構成に使用する
* ルートテーブルは宛先ごとの通信経路を定義する
* インターネットゲートウェイはVPCとインターネットを接続する
* NATゲートウェイはプライベートサブネットから外部へ通信するために使用する
* セキュリティグループはリソース単位のステートフルな通信制御
* ネットワークACLはサブネット単位のステートレスな通信制御
* ロードバランサーは複数のサーバーへ通信を分散する
* 複数AZに分散することで可用性を高められる
* VPCピアリングはVPC同士をプライベート接続する
* トランジットゲートウェイは複数のVPCや拠点を集中的に接続する
* クラウドでも基本はIPアドレス・ルーティング・通信制御の理解が重要
