# ネットワーク冗長化・HA

ネットワーク冗長化は、**機器や経路に障害が発生しても通信を継続できるように、予備の機器や経路を用意する設計**。

HA（High Availability）は、システムやネットワークを**高可用性にするための仕組み**。

---

# 冗長化

冗長化では、単一障害点（SPOF）をなくすことが重要。

```text
冗長化なし

Client
  |
Router
  |
Server

Router障害 → 通信停止
```

```text
冗長化あり

        ┌─ Router A ─┐
Client ─┤            ├─ Server
        └─ Router B ─┘

Router A障害 → Router Bへ切り替え
```

主な冗長化対象：

* ルーター
* スイッチ
* ファイアウォール
* 回線
* サーバー
* 電源
* ネットワーク経路

---

# HA

HA（High Availability）は、障害発生時にもサービスを継続できるようにする考え方。

重要なのは、

**障害をなくすのではなく、障害が発生してもサービスへの影響を小さくすること**。

---

# フェイルオーバー

フェイルオーバーは、**障害が発生した際に、待機系や別経路へ処理を切り替える仕組み**。

```text
通常時

Client
  |
Active
  |
Server


障害発生

Client
  |
Standby
  |
Server
```

切り替えが自動で行われる構成では、障害発生時の停止時間を短縮できる。

---

# アクティブ・スタンバイ

アクティブ系と待機系を用意する方式。

```text
        ┌─ Active
Client ─┤
        └─ Standby
```

通常時はActiveだけが処理し、Activeに障害が発生するとStandbyが処理を引き継ぐ。

## 特徴

* 構成が比較的シンプル
* 障害時の切り替えが分かりやすい
* 待機系のリソースを通常時に有効活用しにくい

---

# アクティブ・アクティブ

複数の機器が同時に処理を行う方式。

```text
        ┌─ Active
Client ─┤
        └─ Active
```

## 特徴

* 通常時から複数機器を利用できる
* 負荷分散にも利用できる
* 構成や障害時の制御が複雑になりやすい

---

# VRRP

VRRP（Virtual Router Redundancy Protocol）は、**複数のルーターで仮想的なデフォルトゲートウェイを構成するためのプロトコル**。

```text
             仮想IP
               |
        ┌──────┴──────┐
        |             |
     Router A      Router B
     Master        Backup
```

クライアントは実際のルーターのIPアドレスではなく、**仮想IPアドレスをデフォルトゲートウェイとして使用する**。

Router Aに障害が発生すると、Router Bが仮想IPを引き継ぐ。

---

# HSRP

HSRP（Hot Standby Router Protocol）は、**複数のルーターでデフォルトゲートウェイを冗長化するためのプロトコル**。

基本的な考え方はVRRPと同じ。

```text
Client
   |
仮想IP
   |
┌──┴──┐
A     B
Active Standby
```

HSRPは主にCisco機器で使用される。

---

# リンクアグリゲーション

複数の物理リンクを**1つの論理的なリンクとして扱う技術**。

```text
Switch A
  ║ ║
  ║ ║  複数リンク
  ║ ║
Switch B
```

主な目的：

* 通信帯域の向上
* リンク障害への耐性向上

1本のリンクが障害になっても、残りのリンクで通信を継続できる。

---

# LACP

LACP（Link Aggregation Control Protocol）は、**複数の物理リンクを束ねてリンクアグリゲーションを構成するためのプロトコル**。

```text
Switch A
  ║ ║
  ║ ║ ← LACP
  ║ ║
Switch B
```

リンクの状態を確認しながら、複数のリンクを論理的に束ねる。

---

# ECMP

ECMP（Equal-Cost Multi-Path）は、**同じコストの複数経路を利用して通信を分散する仕組み**。

```text
          ┌─ Router A ─┐
Client ───┤             ├── Server
          └─ Router B ─┘
```

複数経路を利用することで、

* 負荷分散
* 経路冗長化

を実現できる。

---

# 冗長化と負荷分散

冗長化と負荷分散は目的が異なる。

### 冗長化

**障害時にも通信を継続すること**が目的。

### 負荷分散

**複数の機器や経路に通信を分散すること**が目的。

ただし、ECMPやアクティブ・アクティブ構成のように、両方を実現できる仕組みもある。

---

# 冗長化設計での注意点

冗長化しても、別の場所に単一障害点が残っていると意味がない。

例えば、

```text
Client
  |
Switch
  |
┌─ Router A
└─ Router B
```

としても、ClientとSwitchの間が1本だけなら、Switchやリンクが障害になると通信できない。

そのため、

**機器だけでなく、リンク・経路・電源なども含めて冗長化することが重要**。

---

# 覚えておくポイント

* 冗長化は障害時にも通信を継続するための設計
* SPOF（単一障害点）をなくすことが重要
* HAは高可用性を実現するための考え方
* フェイルオーバーは障害時に別系へ切り替える仕組み
* アクティブ・スタンバイは通常1台が処理し、障害時に待機系へ切り替える
* アクティブ・アクティブは複数台が通常時から処理する
* VRRPは仮想IPによってデフォルトゲートウェイを冗長化する
* HSRPもデフォルトゲートウェイの冗長化に使用される
* リンクアグリゲーションは複数リンクを論理的に束ねる
* LACPはリンクアグリゲーションを構成するためのプロトコル
* ECMPは同一コストの複数経路を利用する
* 冗長化では機器だけでなくリンクや経路も確認する
