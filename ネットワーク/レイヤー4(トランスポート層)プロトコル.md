# トランスポート層プロトコル

## UDP

UDPは、TCPのような信頼性制御を行わず、軽量・低遅延な通信を行いたいアプリケーションなどで使用される。

* コネクションレス型
* 接続確立処理を行わない
* ACKによる確認応答を行わない
* 再送・順序制御・フロー制御・輻輳制御をUDP自身では行わない
* UDPペイロードにUDPヘッダーを付加してUDPデータグラムを作る

### UDPのパケットフォーマット

* 送信元ポート番号
* 宛先ポート番号
* UDPデータグラム長
* チェックサム
* UDPペイロード

### 送信元/宛先ポート番号

アプリケーション（プロセス）を識別するために使用する。

### ポート番号

0～65535の範囲で、以下の3種類に分類される。

* **System Ports**：0～1023
* **User Ports**：1024～49151
* **Dynamic Ports**：49152～65535

Dynamic Portsは、主にクライアント側の送信元ポートとして一時的に使用される。

例：

* UDP 123 → NTP
* TCP 80 → HTTP
* TCP 3306 → MySQL
* TCP 3389 → RDP

※TCPとUDPではポート番号の名前空間は別。

## TCP

TCPは、データ転送の信頼性を必要とするアプリケーションで使用される。

* コネクション型
* 3ウェイハンドシェイクでコネクションを確立
* ACKによる確認応答
* 再送制御・順序制御・フロー制御・輻輳制御を行う
* TCPペイロードにTCPヘッダーを付加してTCPセグメントを作る

### TCPのパケットフォーマット

* 送信元ポート番号
* 宛先ポート番号
* シーケンス番号
* 確認応答番号
* データオフセット
* 予約領域
* コントロールビット
* ウィンドウサイズ
* チェックサム
* 緊急ポインタ
* オプション＋パディング
* TCPペイロード

### 送信元/宛先ポート番号

アプリケーション（プロセス）を識別するために使用する。

### シーケンス番号

TCPデータ内のバイト位置を示し、データの順序制御や再送制御などに使用する。

### 確認応答番号

「次にこのシーケンス番号のデータをください」という意味で、次に受信したいバイトを示す。

ACKフラグが1の場合に有効。

### データオフセット

TCPヘッダーの長さを示す。

### コントロールビット

TCPコネクションの状態を制御するフラグ。

* SYN：コネクション確立
* ACK：確認応答
* FIN：正常終了
* RST：コネクションのリセット

### ウィンドウサイズ

受信側が受け取れるデータ量を送信側に通知する。

### 緊急ポインタ

URGフラグが1の場合に使用され、緊急データの範囲を示す。

### オプション

TCPの拡張機能を通知するために使用する。

#### MSS

TCPペイロードの最大サイズ。

IPv4＋TCPの標準的な構成では、**MSS ≒ MTU − 40バイト**。

#### SACK

受信済みのデータ範囲を選択的に通知し、失われたTCPセグメントだけを再送できるようにする。

## TCPにおける状態遷移

### 接続開始フェーズ

TCPコネクションは**3ウェイハンドシェイク**で確立する。

```text
クライアント → SYN → サーバー
クライアント ← SYN/ACK ← サーバー
クライアント → ACK → サーバー
```

* **アクティブオープン**：コネクションを開始する側
* **パッシブオープン**：コネクションを受け付ける側

### 接続確立フェーズ

TCPは以下の制御を組み合わせて、信頼性のあるデータ転送を行う。

#### フロー制御

受信側の処理能力に合わせて送信量を調整する。

受信側が通知するウィンドウサイズを利用し、送信可能なデータ量を調整する仕組みが**スライディングウィンドウ**。

#### 輻輳制御

ネットワークの混雑状況に合わせて送信量を調整する。

送信可能なデータ量を制御するためのウィンドウを**輻輳ウィンドウ（cwnd）**という。

代表的な輻輳制御アルゴリズムに**CUBIC**がある。

#### 再送制御

パケットロスなどによって失われたデータを再送する。

主な再送のきっかけ：

* **重複ACK**：同じACKが繰り返し届くことでデータの欠落を推測
* **再送タイムアウト（RTO）**：一定時間ACKが返ってこない場合に再送

### 接続終了フェーズ

TCPでは、通信方向ごとに終了処理を行う。

代表的な終了処理はFIN/ACKを使用する**4ウェイハンドシェイク**。

* **アクティブクローズ**：コネクションを終了する側
* **パッシブクローズ**：終了要求を受け付ける側

## UDPファイアウォール

ファイアウォールで通信状態を追跡しながら制御する技術を**ステートフルインスペクション**という。

主に以下のテーブルを使用する。

* **フィルターテーブル**：通信の許可・拒否などのルールを定義
* **コネクションテーブル**：通信の状態を管理

### ファイアウォールのアクション

* **許可**
* **拒否（Reject）**
* **ドロップ（Drop）**

RejectとDropの違いは、拒否を相手に通知するかどうか。

* **Reject**：拒否を通知する
* **Drop**：パケットを破棄し、基本的に応答を返さない

Dropは**Silent Discard**とも呼ばれる。

※実際の応答方法はファイアウォール製品や設定によって異なる。

---

## TCPファイアウォール

UDPファイアウォールと同様に、

* フィルターテーブル
* コネクションテーブル

を利用する。

TCPではコネクションの状態を追跡できるため、コネクションテーブルに状態情報を保持する。

```text
SYN
 ↓
SYN/ACK
 ↓
ACK
 ↓
ESTABLISHED
```

この状態情報を利用して、既存の通信に属するパケットかどうかなどを判断する。

## UDPとTCPの比較

|        | UDP    | TCP   |
| ------ | ------ | ----- |
| コネクション | なし     | あり    |
| 信頼性制御  | なし     | あり    |
| 順序制御   | なし     | あり    |
| 再送制御   | なし     | あり    |
| フロー制御  | なし     | あり    |
| 輻輳制御   | なし     | あり    |
| PDU    | データグラム | セグメント |
| 特徴     | 軽量・低遅延 | 信頼性重視 |

### フロー制御と輻輳制御

* **フロー制御**：受信側の能力に合わせる
* **輻輳制御**：ネットワークの混雑に合わせる

### 通信を識別する5タプル

通信を識別する情報として、以下の5つを使用する。

* 送信元IPアドレス
* 送信元ポート番号
* 宛先IPアドレス
* 宛先ポート番号
* プロトコル
