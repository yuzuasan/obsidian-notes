# イーサネット

## フレームフォーマット

Ethernet IIのフレームは、以下のフィールドで構成される。

* プリアンブル
* SFD
* 宛先MACアドレス
* 送信元MACアドレス
* タイプ（EtherType）
* イーサネットペイロード
* FCS

「宛先MACアドレス」「送信元MACアドレス」「タイプ」を合わせて**イーサネットヘッダー**という。

FCSはフレームのエラー検出に使用され、フレーム末尾にあるため「イーサネットトレーラー」と呼ばれることがある。

### プリアンブル

フレームの先頭に付与されるビットパターン。受信側がフレームを受信するための同期に使用する。

### タイプ（EtherType）

ペイロードに格納されている上位プロトコルを識別する値。

* `0x0800`：IPv4
* `0x0806`：ARP
* `0x86DD`：IPv6

### FCS

フレームが破損していないかを確認するためのフィールド。CRCを利用してエラーを検出する。

## MACアドレス

48ビットのアドレス。

先頭オクテットの下位2ビットには特別な意味がある。

### I/Gビット

* `0`：ユニキャストアドレス
* `1`：マルチキャストアドレス

`ff:ff:ff:ff:ff:ff`はブロードキャストアドレスで、同一LAN上のすべての端末を対象とする。

### U/Lビット

* `0`：ユニバーサルアドレス
* `1`：ローカルアドレス

### OUI

IEEEが組織に割り当てるMACアドレスの識別子。一般的なMACアドレスでは上位24ビットに相当する。

# ARP

IPアドレスからMACアドレスを解決するためのプロトコル。

## フレームフォーマット

以下のフィールドで構成される。

* ハードウェアタイプ
* プロトコルタイプ
* ハードウェアアドレスサイズ
* プロトコルアドレスサイズ
* オペレーションコード（Opcode）
* 送信元MACアドレス / 送信元IPアドレス
* 目標MACアドレス / 目標IPアドレス

Ethernet + IPv4では、

* ハードウェアタイプ：`1`
* プロトコルタイプ：`0x0800`
* ハードウェアアドレスサイズ：`6`
* プロトコルアドレスサイズ：`4`
* ARP Request：`1`
* ARP Reply：`2`

ARPのEtherTypeは`0x0806`。

## ARPテーブル

IPアドレスとMACアドレスの対応関係を一定時間保持するテーブル。

# L2スイッチング

イーサネットフレームをMACアドレスに基づいて転送する技術。

## MACアドレステーブル

送信元MACアドレスと、そのMACアドレスを学習したポート番号を管理するテーブル。

スイッチは受信したフレームの**送信元MACアドレスを学習**し、**宛先MACアドレスを見て転送先を決定**する。

## フラッディング

宛先MACアドレスがMACアドレステーブルに存在しない場合などに、受信ポート以外の同一VLAN内のポートへフレームを転送する動作。

---

# VLAN

1台のL2スイッチ上に複数の論理的なブロードキャストドメインを作る技術。

## ポートVLAN

1つのポートに1つのVLANを割り当てる方式。

主にアクセスポートで使用する。

## タグVLAN

イーサネットフレームにVLAN情報を「VLANタグ」として付加する方式。

1つのポートで複数のVLANのフレームを扱える。

IEEE 802.1QのVLANタグは以下で構成される。

* TPID：802.1Qタグを識別
* PCP：優先度
* DEI：破棄対象の指標
* VID：VLAN ID

VLANタグは送信元MACアドレスとタイプの間に挿入される。

## ネイティブVLAN

トランクポートでタグの付いていないフレームを受信した場合に、そのフレームを所属させるVLAN。

# STP

L2ネットワークで発生する**ループを防止するためのプロトコル**。

スイッチ間に冗長経路があるとL2ループが発生する可能性がある。STPは冗長経路の一部を論理的にブロックし、ループを防止する。

## L2ループ

L2ループが発生すると、以下の問題につながる。

* ブロードキャストストーム
* MACアドレステーブルの不安定化
* 同一フレームの重複転送
* ネットワーク帯域の圧迫

L2にはIPのTTLのような仕組みがないため、ループしたフレームがネットワーク内を循環し続ける。

## BPDU

BPDU（Bridge Protocol Data Unit）は、STPでスイッチ間の情報交換に使用するフレーム。

BPDUの情報をもとに、Root Bridgeや転送経路を決定する。

## Root Bridge

STPネットワークの基準となるスイッチ。

**Bridge IDが最も小さいスイッチ**がRoot Bridgeになる。

Bridge IDは主に以下で構成される。

* Bridge Priority
* MACアドレス

## Port Role

### Root Port

Root Bridge以外の各スイッチで選出される、Root Bridgeへの最適経路となるポート。

### Designated Port

各ネットワークセグメントで、フレーム転送に使用するポート。

### ブロックされるポート

ループを防止するため、冗長経路の一部を転送に使用しない。

## Path Cost

Root Bridgeまでの経路を評価するための値。

基本的に**Path Costが小さい経路が優先**される。

## STPと冗長化

STPは冗長リンクを削除するのではなく、**一部を論理的にブロックしてループを防止する**。

転送経路に障害が発生した場合は、ブロックしていた冗長経路を利用して通信を復旧できる。

```text
通常時

Switch A
   |\
   | \
   |  \
   |   Switch B
   |  /
   | /
   X
ブロック
```

## RSTP

RSTP（Rapid Spanning Tree Protocol）は、STPの収束を高速化したプロトコル。

障害やトポロジー変更時の経路切り替えを、従来のSTPより高速に行える。

## 覚えておくポイント

* STPはL2ループを防止する
* BPDUを使ってスイッチ間で情報を交換する
* Bridge IDが最も小さいスイッチがRoot Bridgeになる
* Root PortはRoot Bridgeへの最適経路
* Designated Portはセグメントの転送ポート
* 冗長経路の一部をブロックしてループを防止する
* 障害時には冗長経路を利用して復旧できる
* RSTPはSTPの収束を高速化したもの
